# Conversation state and reconfiguration

AiConversation owns its current immutable DefinitionSelection, immutable array of completed ConversationTurn values and independent GUID. The selection retains a captured DefinitionCatalog, including its declarative content; the conversation does not publish context updates or dispose injected clients. AiConversationFactory creates fresh runtime state for each call.

Interlocked.CompareExchange acquires an operation gate for SendAsync, Preview and Configure. Overlap and reentrancy throw InvalidOperationException immediately rather than queueing. Configure passes a new builder to the callback and commits its immutable selection only after successful return. UseContext clears role, rule sets, rules and reusable data even when selecting the same context again. ClearRole, ClearRules and ClearContexts permit narrower transitions.

ApplyDefinitions updates the context independently of the conversation gate and does not change a conversation's captured content. Configure(config => config.RefreshDefinitions(context)) explicitly captures the latest catalog while retaining the selected role, rule sets, rules, reusable data and full history. Refresh requires the original context instance: matching DomainId or definition IDs alone is insufficient, because the catalog's ContractIdentity token must match. UseContext captures the supplied context's latest catalog and clears selections while retaining history. A failed refresh or a later exception in the configuration callback publishes no conversation changes. Context updates made independently by application code are not rolled back by a failed callback.

A send checks cancellation, determines eligible/selected history, creates a composer, applies local overrides, sets the final prompt, captures a request, executes, checks cancellation again, and commits a completed exchange. Exceptions, malformed typed output, cancellation and unsupported response content leave state untouched and release the gate. External provider work cannot be rolled back if cancellation arrives after dispatch.

A short state lock protects publication and GetState reads. The lock is never held across user callbacks or asynchronous provider work. GetState returns a detached immutable view of committed state, including while a send is in flight. Successful IDs increase from one without gaps caused by failed attempts.

ConversationTurn records framework request composition, selected configuration IDs, eligible/transmitted history IDs, and the original current-user/assistant exchange. It does not store mutable ChatResponse objects or provider token usage; SDK-returning SendAsync overloads expose those to callers. SendValidatedAsync returns an outcome envelope without SDK metadata. Non-assistant roles and non-TextContent responses fail explicitly to avoid silent loss or elevation of authority. Refreshing definitions never rewrites committed turns.

Preview uses the same composition path without sending or committing. It neither reserves a turn nor guarantees that a later send uses unchanged state.

Request overrides receive AiRequestConfiguration rather than the executable composer. They can remove roles, rules and contextual data without modifying active configuration, but cannot dispatch extra requests through that object. Preview is rejected while another operation is active, just like sends and configuration changes. Empty provider response message lists fail before commit.

ConversationState is serializable data, verified by a JSON round-trip test. It contains configuration IDs and completed request/exchange snapshots, not a restorable runtime conversation or the complete active definition catalog. Optional [definition serialization](DefinitionSerialization.md) is a separate contract. The framework supplies no durable storage backend or runtime restore API. A future conversation adapter must define content/version resolution against application catalogs and validate untrusted persisted state. Full history currently grows for the session lifetime.

SendValidatedAsync holds the same operation gate through parsing and domain checks. It returns rejected attempts without recording them: Invalid, Unverifiable and structurally failed candidates never become replayable history. Valid and NotValidated typed responses commit text plus immutable Validation metadata. Existing send methods record NotValidated. Typed objects and SDK responses are not stored. Rejected attempts have no committed turn ID; the returned request snapshot associates diagnostics with the attempted configuration. Applications own durable attempt auditing.
